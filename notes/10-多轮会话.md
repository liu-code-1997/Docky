# 10 · 多轮会话(M12)

把"一问一答的无状态 RAG"升级成**能记住上文的多轮小助手**。核心难点不在存储,
而在**指代消解**:用户第 2 轮问"它能限定类型吗?",这个"它"检索器看不懂——
必须先把它补成一个**自包含的独立问句**再去检索。

## 组成(四块,各自可测)

1. **SessionStore(会话历史存储)** —— `InMemorySessionStore`,按 `session_id`
   存 `list[Message]`。抽象成 ABC(`get_history`/`append`),将来换 Redis/DB 只换实现。
   `get_history` 返回拷贝,防外部改动内部状态。
2. **condense-question(问题改写)** —— `condense_question(llm, question, history)`:
   有历史时让 LLM 把"带指代的追问"改写成"独立问句";**无历史直接返回原问,不调 LLM**
   (第 1 轮零开销);LLM 空回复兜底回原问(不崩、不比单轮差)。
3. **generate 带历史(可加)** —— `build_prompt/answer` 加可选 `history` 参数,
   在 system 与【资料】之间插入历史对话块。**默认空列表 = 与单轮字节一致**(不动老路径)。
4. **ConversationalRag(编排)** —— `chat(session_id, question, library=None)`:
   ①取历史 → ②`condense` 成独立问句(仅用于检索)→ ③用独立问句检索 →
   ④用**原始问题** + 最近 `history_turns` 轮历史生成 → ⑤把 user/assistant 两条追加进 store。
   关键不变量:**检索用 condense 后的独立问句,生成用原始问题**(原问更自然,改写问更利检索)。

## 装配 & 接口

- `/chat` 端点:`POST {session_id, question, library?}`,未配置 conversation 时 503
  (与 `/agent/ask` 同款保护)。`create_app(..., conversation=None)` 新增可选参数,
  单轮 `/ask`、`/agent/ask` 完全不动。
- `scripts/serve.py` 复用现有 retriever 闭包(含改写/重排/多查询)装配 ConversationalRag。
- 配置:`history_turns=6`(喂生成的最近轮数)、`condense=True`(是否开问题改写)。

## 实机演示(仅演示,无指标)

两轮对话,`scripts/demo_multiturn.py`:

```
第 1 轮 用户问:FastAPI 路径参数怎么声明?
  → 命中 tutorial-path-params,给出 file_path: str 的声明示例。
第 2 轮 用户问:它能限定类型吗?
  ↳ condense 改写:FastAPI中路径参数能否指定类型?     ← "它"被补成"路径参数"
  ↳ 命中来源:['fastapi/tutorial-path-params.md', 'fastapi/tutorial-first-steps.md']
  ↳ 回答顺着上下文谈"路径参数可通过类型注解限定类型",衔接自然。
```

**结论**:condense 成功消解了跨轮指代("它"→"路径参数"),检索命中正确文档,
回答承接上文——多轮能力打通。这是**演示级验证**(定性),不是指标(多轮质量的
量化评估集未建,属非目标)。

## 非目标(YAGNI)

- 不做 compaction / 长期记忆 / Redis 持久化(接口留好,按需换实现)。
- 不做 agent 的多轮(只做 pipeline 侧多轮)。
- 不建多轮评估集(演示验证即可,量化留待有需要时)。

## 方法论

多轮的坑集中在"指代 + 检索"的错位:直接拿"它能限定类型吗?"去检索必然跑偏。
解法是把**检索输入**和**生成输入**分开——检索要自包含的改写问句,生成要原始的自然问句 +
历史。第 1 轮不调 condense(省一次 LLM)、空回复兜底回原问,是"不因新增能力而劣化老路径"
的一贯纪律。
